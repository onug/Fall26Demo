The Agentic Control Plane, Running on One Machine

onug-plane @ 21a80f2· 2026-10-08· Peter Campbell, Head of Collaborative Working Groups and Security Research

onug-plane is a runnable build of the WG1 Agentic Control Plane, assembled from open-source components on one laptop. Two NOC personas, built on two different agent frameworks, work a real source of truth (NetBox) and a real emulated network (three Nokia SR Linux routers). The agents carry no credentials and decide nothing about their own permissions. Identity, policy, approvals, model access, audit and the kill switch all live in the plane, outside the agent.

Architecture

3 namespaces · 1 cluster

Everything runs in one kind Kubernetes cluster. Calico enforces NetworkPolicy and gVisor sandboxes the agent pods. The agents namespace can reach exactly two things, agentgateway and DNS, so every tool and model call passes the same choke point.

A tool call, end to end

MCP path
  1. The persona fetches a JWT-SVID from the SPIRE Workload API with audience agentgateway.
  2. It sends MCP tools/call to agentgateway with the SVID as a bearer token.
  3. The gateway validates the JWT strictly against SPIRE's JWKS, then checks kill rules, the CEL allow-list for the server and tool, and the rate limit. refused A refusal returns 4xx (JSON-RPC -32003 for rate limits) and is journaled as denied:policy, quarantined, stopped or budget.
  4. The gateway forwards the call with the SVID passed through. It holds no credentials of its own.
  5. The supervisor re-verifies the SVID with no clock leeway, runs the injection filter, and checks composite rules against the persona's recent journal window.
  6. If the tool is destructive and the persona is at rung 3, the supervisor opens a Temporal ApprovalWorkflow and holds the call. human gate It proceeds only on plane approve; deny or timeout ends it.
  7. The supervisor calls netbox-mcp or gnmi-tools with the upstream bearer it reads from OpenBao.
  8. The result is scanned and secrets are redacted before it goes back through the gateway to the persona. returned
  9. The gateway emits one span per request and the supervisor emits one per decision (decision, argument hash, approver). Both become journal records.

Tool lists are filtered per persona, so an ungranted tool does not exist from that persona's point of view. Destructiveness comes from MCP annotations, with a per-persona classify override.

A model call

LLM path
  1. The persona posts /v1/chat/completions to the gateway with its SVID and a model alias such as local/small.
  2. The gateway checks the JWT, kill rules and the per-model allow-list.
  3. LiteLLM's custom_auth maps the SVID to the persona's virtual key. If the mapping fails, the call is refused.
  4. LiteLLM enforces the key's model allow-list and budget. A hard stop returns 429 denied:budget.
  5. The alias is routed to qwen3:1.7b locally or to claude-opus-5-5, and a span records tokens and cost.

Model aliases are pinned in versions.env. frontier/default resolves to Claude Opus 5.5 when an Anthropic key has been loaded into OpenBao. Without one, it falls back to the local qwen3:4b.

Local models are charged a shadow price, so spend attribution covers every call and not only the paid ones. The provider key is typed into OpenBao by the operator and is never written to disk.

From registry entry to running persona

Proof P4
  1. registry/personas/<persona>.yaml declares the framework, rung, tools, models, budgets, behaviour limits and approval rules.
  2. plane validate checks the schema, the rung rules (a rung-1 persona may hold only read-only tools) and the security invariants.
  3. plane render writes build/<persona>/ (Kubernetes manifests, SPIRE entry, NetworkPolicy), an A2A Agent Card with a JWS signature, and a CycloneDX 1.7 AIBOM with a cosign bundle.
  4. plane apply admits the persona only if it is certified, its signatures are valid and the build is fresh. admission
  5. On admission the plane creates the SPIRE entry, gateway and supervisor config, the LiteLLM key and the Deployment, and journals persona_applied.

Onboarding never touches enforcement code. Proof P4 onboards noc-operator from its YAML alone and checks that nothing changed outside registry/ and build/.

Kill path

Proof P3

The drift detector scans the journal every 2 seconds against each persona's declared normal behaviour over a 24-hour window: tool calls per minute, tokens per hour, destructive calls per day, working hours, allowed servers and denial bursts. On a violation it acts on three systems at once and journals the quarantine with the rule, the numbers and the triggering span.

Proven, not claimed

P1 no-secrets: each agent pod, including the whole gVisor sandbox memory, is searched for every secret in OpenBao, with planted canaries to show the search works. P2 journal: every gateway request during the demo has exactly one journal record, sampled records verify in immudb and are locked in MinIO. P3 kill: quarantine within 10 s, refused at the gateway, SPIRE entry gone. P4 onboard: a persona onboarded from YAML alone, with its destructive call gated.

Verified end to end on Apple Silicon with 12 GB given to Docker. x86-64 and Linux builds are prepared but have not been run end to end.
